# Xbox console remote-play protocol findings (2026-10-16)

Scope: primary protocol/source inspection only; no console session, credentials, or packet capture. Conclusions about retail Series X behavior remain subject to device verification. No implementation code copied.

## LAN and ICE

- Xbox Remote Play runs the game on the user's console; Microsoft's public overview establishes this distinction but does not document consumer xHome signaling or promise LAN routing. [Microsoft GDK overview](https://learn.microsoft.com/en-us/xbox/gdk/docs/features/common/game-streaming/game-streaming-overview), [official Remote Play requirements](https://www.xbox.com/en-US/consoles/remote-play).
- XStreaming uses `/v5/sessions/home/play`, then session resources including `state`, `configuration`, `sdp`, and `ice`; ICE POST uses `messageType: iceCandidate` with a candidate array. It lists home servers via `/v6/servers/home`. This is an interoperating client's implementation, not a Microsoft compatibility contract. [XStreaming xCloud API, pinned revision](https://github.com/Geocld/XStreaming/blob/9e6a21251c379c861cc48f105530895dab9180c3/src/xCloud/index.ts).
- **Candidate type is not proof of LAN locality.** Greenlight synthesizes `typ host` IPv4 candidates from Teredo's public mapped endpoint, including port 9002. XStreaming likewise expands Teredo into several IPv4 endpoints labeled host. A host filter can therefore retain public endpoints. [Greenlight ICE implementation](https://github.com/unknownskl/greenlight/blob/0bf80599bf7c9c102a939ce994b5118cd7cb57ce/packages/player/src/client/lib/ice.ts), [XStreaming Teredo handling](https://github.com/Geocld/XStreaming/blob/9e6a21251c379c861cc48f105530895dab9180c3/src/xCloud/teredoCandidates.ts).
- I found **no primary captured Series X candidate set proving that its private LAN endpoint always has type host**. Under ICE terminology host means a directly bound interface endpoint; srflx is learned through STUN. Neither name independently establishes the route. If Xbox returns a private same-subnet address labeled srflx, its address may still be suitable for local delivery; rejecting it solely by type would be a product restriction rather than an established Xbox requirement. [RFC 8445 sections 2.1 and 5.1.1](https://www.rfc-editor.org/rfc/rfc8445.html#section-5.1.1).
- Native ObjC `RTCIceTransportPolicy` offers None, Relay, NoHost, and All; **no host-only or private-subnet-only policy**. Network policy concerns network cost, not an endpoint allowlist. Removing ICE servers limits gathering, and filtering candidates before signaling/`addIceCandidate` limits explicitly supplied endpoints, but does not establish an absolute transport boundary. [libwebrtc RTCConfiguration.h](https://webrtc.googlesource.com/src/+/refs/heads/main/sdk/objc/api/peerconnection/RTCConfiguration.h).
- **Signaling filters alone cannot guarantee all ICE traffic stays on LAN:** ICE learns remote peer-reflexive candidates from authenticated incoming checks and performs triggered checks against their source addresses. A selected-pair statistics check is after connectivity establishment, and only proves the observed pair at that time. A hard no-WAN guarantee needs enforcement in the actual transport/packet layer (or equivalent system route/firewall boundary), not a post-connection UI check. Same-subnet private IPv4 plus an approved local interface is a useful deliberately narrow admission policy, but address checks alone do not prove physical topology when routing/VPNs are involved. [RFC 8445 sections 7.3.1.3–7.3.1.4](https://www.rfc-editor.org/rfc/rfc8445.html#section-7.3.1.3). This is an inference from standard ICE behavior and the exposed native API, not a tested bypass against this build.

## SmartGlass LAN discovery

- Discovery has a six-byte header: packet type uint16, unprotected payload length uint16, version uint16; protected length exists only for connect packets. Request payload: flags uint32, client type uint16, minimum version uint16, maximum version uint16. All numbers are big endian. Current request is flags 0, desktop type 3, range 0–2, header version 0 and payload length 10, consistent with the reference implementation. [Primary packet schema](https://github.com/OpenXbox/xbox-smartglass-core-python/blob/96e1e0a45db347f66101c3df5eec3f7cb92d1236/xbox/sg/packet/simple.py#L20).
- **Confirmed parser defect:** response payload starts flags uint32 + type uint16 + name SGString. Thus the name length starts at absolute byte **12**, not current byte 14 (`6 + 8`). The documentation's offset table is internally inconsistent; use the actual schema. Remaining fields are UUID string, last error uint32, DER certificate. Certificate subject CN identifies Live ID. [Primary response schema](https://github.com/OpenXbox/xbox-smartglass-core-python/blob/96e1e0a45db347f66101c3df5eec3f7cb92d1236/xbox/sg/packet/simple.py#L46), [protocol documentation](https://openxbox.org/smartglass-documentation/simple_message/).
- Discovery is presence detection, distinct from account-associated device listings or ConnectedStandby state. Fixing parsing cannot produce responses if a probe actually receives zero datagrams. Broadcast/multicast delivery, device sleep behavior, interface selection, and UDP 5050 reachability require separate live evidence. [OpenXbox protocol basics](https://openxbox.org/smartglass-documentation/basics/), [discovery description](https://openxbox.org/smartglass-documentation/simple_message/#discovery-packet).

## Wake

- Local SmartGlass wake is packet `0xDD02`, with a Live ID SGString, sent by broadcast/multicast or known console IP; it has no response, and reference docs recommend repetition. This is separate from online XCCS commands. [OpenXbox Power On](https://openxbox.org/smartglass-documentation/simple_message/#power-on-request).
- Online reference implementation POSTs to `https://xccs.xboxlive.com/commands`, contract 4, skillplatform RemoteManagement, with Power/WakeUp, linkedXboxId, SmartGlass source ID, session ID, and parameters defaulting to `[{}]`. Current repo parameters `[]` differs; no direct evidence that this causes a hang. [OpenXbox web API provider](https://github.com/OpenXbox/xbox-webapi-python/blob/672f34f256f18640d387147867950234fc2e140f/xbox/webapi/api/provider/smartglass/__init__.py#L125), [command construction](https://github.com/OpenXbox/xbox-webapi-python/blob/672f34f256f18640d387147867950234fc2e140f/xbox/webapi/api/provider/smartglass/__init__.py#L375).
- **Response parsing concern:** reference CommandResponse makes `result` optional, while destination, op_id and status are required. Requiring nonnil result can reject valid-shaped acknowledgements. Wake acknowledgement does not prove powered-on state; reference API exposes operation-status queries separately. An in-flight request lasting minutes requires an explicit timeout/cancellation investigation independently of response validation. [Response models](https://github.com/OpenXbox/xbox-webapi-python/blob/672f34f256f18640d387147867950234fc2e140f/xbox/webapi/api/provider/smartglass/models.py#L127).
